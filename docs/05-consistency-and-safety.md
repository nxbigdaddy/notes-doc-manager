# 05 — 文件一致性、安全与恢复

## 1. 不可违反的规则

1. 扫描、预览、索引、备份和恢复管理信息不得写回已有正文。
2. 移出文档库不等于删除文件；首版不提供已有文件删除入口。
3. 不能把库离线、权限失败、取消扫描当作全部文件已被删除。
4. 不可靠的移动关系不自动迁移标签；宁可保留缺失记录等待用户确认。
5. 不执行文档中的代码、命令、链接或脚本。
6. 不通过更高权限绕过访问失败，不自动启动管理员模式。
7. 已保存盘符不等于永久本地访问许可。注册、重启扫描、预览、身份采集、新建及监听均先确认固定NTFS卷，再访问路径；添加新库时不resolve其他已保存的旧根。

## 2. 扫描与监听

改用 `watchdog.Observer`，把操作系统事件统一交给 FileChangeMonitor [S6]。本项目不把监听当完整审计流水：重复、乱序、订阅中断、Windows 后端漏失或目录改名均按“需要重新检查”的信号处理。

watchdog 的公开事件接口不保证把所有底层溢出完整上报。本项目必须持续补偿扫描，并监测 Observer / emitter 线程存活、异常及积压；不把“没有错误回调”等同于“没有漏事件”。

### 2.1 初次及启动扫描

1. 检查根目录可用性、路径范围和重解析点规则。
2. 先订阅监听并缓冲事件，再开始枚举，减少扫描和监听之间的空档。
3. 分批登记文件；按路径匹配已有文档，保持管理信息。
4. 记录扫描代次以及各子树成功覆盖范围。
5. 只对完整成功覆盖区域内未出现的旧记录标记 missing。
6. 取消、枚举异常、权限失败或库断开时，不进行受影响范围的缺失清算。
7. 枚举完成后处理缓冲事件，再验证 dirty 子树。
8. 原型须验证递归订阅对重解析点、后续新建链接和根目录失效的处理；应用端过滤事件不能替代“不越界读取”的扫描规则。监听不可用时明确进入轮询补偿状态并允许重试。

### 2.2 日常事件

- 初值防抖 500 ms，同路径事件合并。
- 创建、修改事件检查文件最终状态后排队索引。
- 删除事件先标记待验证，延迟确认，兼容编辑器原子替换保存。
- 文件夹新增、移动和改名触发受影响子树扫描，不假定每个子文件都有事件。
- rename 只有关系完整且目标无冲突时才保留身份；复杂事件组合退化为扫描。
- 已检测到的溢出、疑似事件漏失、队列饱和或订阅失效设置 dirty 标志并补扫；内部队列不能配置硬上限时，通过合并提示、监测积压和重建订阅限损。

0.4.0对可信文件移动另外保留短时提示。每次重订阅推进epoch，旧handler事件不进入新集合；消费路径和移动提示必须原子完成。自动关联前仍需真实文件身份/路径/人工信息验证，提示本身不能授权改管理关系。拒绝后保留缺失记录，不以不确定信息覆盖标签。

### 2.3 补偿策略

- 启动、手动刷新、监听异常/疑似溢出、库恢复在线、规则改变：补扫相应范围；监听失败后的轮询不是永久隐藏的降级。
- 运行期间每 15 分钟做元信息核对；时间为可调设计初值。
- 若大小和时间未变，普通核对可能无法发现内容变化。每 24 小时安排一次限速正文哈希核验，启动时执行逾期任务。
- 提供“完整重建正文索引”，无条件重读所有符合条件的文件。
- 目录持续高频变化时保持“尚未同步完成”状态，不承诺固定收敛时间。

## 3. 文件读取与编码

### 3.1 稳定读取

- 使用允许其他程序读写/删除的共享方式只读打开，不长时间持有文件句柄。Windows 实现封装 `CreateFileW` 的只读访问和 `FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE`，通过受控 `ctypes` 适配并明确句柄归属；普通 Python `open()` 不作为具有该共享契约的保证 [S17]。
- 读取前后核验文件元信息和任务代际，不一致则延后重试。
- 重试初值：0.5 秒、1 秒、2 秒、4 秒、8 秒，之后显示失败；下一事件或用户重试可恢复。
- 文件锁定或持续写入时不无限占用工作线程。
- 预览限制 256 KiB 源字节，正文索引限制 5 MiB 源字节；使用 `codecs` 增量解码器，预览截断不把“还差后续字节”误当乱码，全文结束才验证最终解码状态 [S14]。

### 3.2 解码顺序

1. 若用户设置了该文档编码 override，优先使用；与 BOM 冲突时展示警告。
2. 否则识别 UTF-8、UTF-16、UTF-32 BOM，先识别较长 BOM，避免前缀误判。
3. 无 BOM 时尝试严格 UTF-8 解码。
4. 失败则标记 `needs_encoding`，由用户选择 GB18030、GBK 或其他已支持编码；不把猜测当成正确结果。
5. 使用 Python `codecs` 的编码白名单，校验 `utf-8`、`utf-16-le/be`、`utf-32-le/be`、`gbk`、`gb18030` 等实际可用项；冻结包也验证 `encodings` 子模块，默认 `errors="strict"`，不根据机器 locale 偷改编码 [S14]。
6. 二进制检测在考虑编码后进行，不能仅因 UTF-16 含 NUL 字节就认定二进制。
7. 已知编码文件解码失败时提示，不通过静默替换字符生成“成功”全文索引。

预览开头可解码不代表全文有效；全文索引独立验证全部允许读取的内容。对无 BOM 的其他编码无法保证自动识别，用户可手动纠正。空文件属于有效文档。

## 4. 新建文档的安全边界

- 仅在启用、在线文档库内的现有目录新建。
- 文件名拒绝路径分隔符、`.`、`..`、Windows 保留设备名、ADS 冒号、非法字符以及尾随空格/句点。
- 解析规范路径并验证根目录边界与重解析点；对敏感文件操作不得仅依赖字符串拼接。
- 使用 Python `open(path, "x", encoding="utf-8")` 的排他新建语义，捕获 `FileExistsError`；不使用 `"w"` 截断已有文件，不以 exists 预检查代替创建时排他校验。首版创建空文件，不写 BOM。
- 创建后关闭句柄，再登记和启动编辑器；失败时保留已创建文件并显示确切路径。
- 不自动创建一串用户未确认的父目录，不自动覆盖，不以删除文件“回滚”数据库失败。
- 本项目不是防御同权限恶意进程修改目录结构的安全沙箱；路径验证不能作此保证。

## 5. 管理信息备份

Python `sqlite3.Connection.backup()` 对接 SQLite 备份 API [S4/S9]。本项目不直接复制正在使用的主数据库文件来冒充一致性备份。

在备份工作线程内创建专属源/目标连接，使用分页步进与 progress 回调报告进度及取消；`pages` 控制内部步长，不表示调用只做一页即返回。备份仍是阻塞调用，不能放 GUI 线程。SQLite 在线备份支持与其他连接访问协调，但可能因忙锁或持续写入重试，不再沿用其他语言驱动“整段必然阻塞写入”的假设。恢复/迁移前保护备份由应用主动暂停写任务以限定状态边界。

两类备份：

1. **本机数据库快照**：使用一致性备份 API，适合故障恢复。
2. **JSON 逻辑导出**：从一致性读取快照导出，适合检查和迁移。

策略初值：

- 元数据有修改时，每日首次空闲创建备份；迁移、替换恢复前额外创建。
- 每类普通自动备份保留最近 7 份，只有新备份验证成功后才清理旧备份。
- 恢复/迁移前的保护备份单独保留到用户确认新状态，不立即按轮换清理。
- 同磁盘备份仅防逻辑损坏，不防磁盘损坏；提示用户导出到另一个可靠位置。
- 不把新旧搜索缓存纳入管理信息备份，不导出正文。
- 导出先写同目录临时文件，完成并校验后发布最终文件；失败不覆盖已有有效备份。

## 6. 恢复与损坏处理

### 6.1 逻辑恢复

v0.3 采用数据库事务方案，替代 v0.2 提议的数据库文件切换：

1. 验证备份格式、版本、大小、路径、唯一性和关联完整性。
2. 展示替换影响；用户确认。
3. 在应用写任务队列中执行，取得 Store 锁，对现有元数据做一致性保护备份；并发查询不能观察半导入状态。
4. 验证整个备份后，在 metadata.db 的单个显式事务中替换管理记录，失败回滚；不替换数据库文件或假定多文件原子切换。
5. 新记录设为待核验、提升正文代际；旧索引即使清理未完成也不能成为有效结果。
6. 清理/重建搜索库，重新建立监听和扫描。编辑器等机器配置不自动恢复。
7. 标准库连接在各调用所属线程显式关闭；崩溃后的数据库事务回滚依赖 SQLite，仍需扩充进程级故障注入验收。

从头到尾不重建、移动或覆盖原文档。

0.2.0已实现每日自动备份、七份自建快照轮换和跨重启到期内容核验。自动快照使用UTC自然日调度，只在管理信息发生变化或保护状态异常时生成；手动提前备份不创建无变化重复副本。时钟回拨时重新评估到期状态，轮换按登记的成功顺序而非墙钟排序，避免删除刚创建的快照。

读取瞬态错误采用有界退避；取消、缺失、路径违规、编码待确认等不自动无限重试。旧备份的清理只涉及验证后的所属普通文件，非递归；保护快照、未知文件和不安全路径保留，不绕过权限。

### 6.2 损坏分级

| 故障 | 行为 |
|---|---|
| 当前搜索缓存损坏 | 停止正文搜索，保留文件名搜索和标签；提示重建自己的缓存，不覆盖未知未来版本 |
| metadata.db 损坏 | 禁止继续写入；保留故障副本，引导恢复，不静默创建空库覆盖 |
| 磁盘写满 | 暂停写入、提示释放空间；不清理用户文件 |
| 备份失败 | 保留现有有效备份；清楚显示未备份状态 |
| 恢复中断 | 依恢复标记与保护备份恢复一致状态；不同时启用两个写入者 |

## 7. 隐私与日志

- 默认无账号、遥测、自动上传和网络请求。
- 数据库、缓存和备份默认未做应用级加密，使用用户目录访问控制；这不是加密保险箱。
- 标签、文件名、绝对路径同样可能敏感，导出前提示。
- 日志默认只包含事件类型、文档 ID、错误码、耗时和计数，不包含正文、搜索词、完整路径或未经清洗的异常信息。
- 使用标准库 `logging` 配合 `RotatingFileHandler`；异常先转换为可控错误码，不能通过默认 traceback 或对象 repr 绕过脱敏。
- 初值：单日志 5 MiB，保留 5 份；失败不持续无限刷屏。
- 用户主动生成诊断包前预览内容并脱敏，不附带数据库正文缓存。
- 停用文档库后安排清理其搜索缓存，但说明普通数据库删除不等于取证级安全擦除；旧备份也可能保留管理信息。

## 8. 发布安全

- 用户配置或恢复的可执行文件路径属于可执行配置，未经确认不自动启动。
- 不执行文件内容，不启动 shell，不提供任意命令插值。
- 锁定 Python、wxPython、watchdog、PyInstaller 及传递依赖；记录实际 wxWidgets、SQLite 和原生 DLL 版本，发布前检查来源、许可证及已知问题。
- PyInstaller 是分发工具，不是代码加密或应用沙箱。发布包验证资源加载、编码、SQLite FTS5 和外部进程 DLL 环境，不能只检查生成了 exe [S11/S18]。
- 首发不捆绑 Notepad3；将来若分发或修改上游，单独审核相应版本和第三方组件许可 [S10]。

## 9. 智能列表边界（0.8.0）

- 保存查询是管理数据，可能包含敏感搜索词和目录信息；随管理备份保存，但不得写入诊断日志，不自动上传。
- 只接受有限过滤字段与版本化JSON，不存SQL、脚本、模板表达式或外部执行配置。
- 已删除标签、不存在/停用文档库的引用不得移除后继续查询；保留定义并提示修复，避免误展示更大范围。
- 首次保存前保护备份，事务升级metadata schema2，旧程序拒绝写入；新format2备份同样让旧程序拒绝而不是丢弃列表。
- 删除列表只删除筛选定义；原文件、标签和收藏不变。恢复旧备份导致列表清空属于显式替换，确认界面必须告知。
