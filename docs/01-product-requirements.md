# 01 — 产品需求

## 1. 定位与目标

为已经习惯 Notepad3 的用户增加“文档管理层”，解决文件散落、分类不便、反复寻找和打开成本高的问题。

目标：

1. 不更换编辑器即可形成“创建 → 编辑 → 保存 → 检索 → 再编辑”的闭环。
2. 文件夹负责真实位置，标签负责跨文件夹分类。
3. 文件保持开放，不把正文锁进专有数据库。
4. 本地优先，不要求登录，不上传文档。

不按“文件由哪个程序创建”识别文档；文档库路径、扩展名、排除规则共同决定管理范围。

实现方案已切换为 **Python + wxPython + SQLite**，不改变本文功能范围和优先级。首版仍是独立 Windows 桌面应用，不新增浏览器界面、内置编辑器或跨平台交付要求。正式验收暂定 Windows 11 x64，同时验证本机 Windows 10 Pro 22H2 x64 的实际兼容性；兼容范围由测试结果决定。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 文档库 | 用户主动添加的一个根目录及其符合规则的子目录文件 |
| 文档 | 已登记的文件记录；即使文件暂时缺失，也可保留管理信息 |
| 分类 | 文件夹代表物理分类；标签代表逻辑分类 |
| 索引 | 从已保存文件提取的可重建检索数据 |
| 最近打开 | 管理器成功发起外部编辑请求的最近记录，不追踪全部系统编辑活动 |
| 移出文档库 | 停止管理该根目录，不删除磁盘文件 |
| 管理信息备份 | 文档路径关联、标签、收藏、设置等，不包含正文 |

## 3. 首版需求

优先级：`P0` 为首版必需；`P1` 为首版完善项，允许经评审调整；`P2` 为后续版本。

| 编号 | 功能 | 优先级 | 业务规则 |
|---|---|---|---|
| FR-001 | 添加和扫描文档库 | P0 | 主动选择目录；扫描显示进度，可取消、重试 |
| FR-002 | 多文档库与排除规则 | P0 | 拒绝重复和父子重叠根目录；排除规则变更可触发重扫 |
| FR-003 | 文档浏览 | P0 | 文件夹、名称、扩展名、修改时间、大小、标签、状态 |
| FR-004 | 新建文档 | P0 | 指定现有可写目录，默认 `.txt`，可选 `.md`；UTF-8 无 BOM |
| FR-005 | 调用 Notepad3 | P0 | 配置可执行文件路径；打开失败保留文档和管理信息 |
| FR-006 | 只读预览 | P0 | 纯文本预览、换行、编码提示；不在管理器中编辑 |
| FR-007 | 文件名和正文搜索 | P0 | 支持中文、短词、特殊字符；可筛选文档库、标签 |
| FR-008 | 标签管理 | P0 | 标签增删改；文档多标签；不改变文件位置 |
| FR-009 | 收藏与最近打开 | P0 | 独立于正文，跨重启保存；最近列表默认展示 100 条 |
| FR-010 | 外部变化刷新 | P0 | 监听 + 补偿扫描；展示索引状态、重试入口 |
| FR-011 | 管理信息备份与恢复 | P0 | 导出可读 JSON；校验后替换恢复；恢复前先备份 |
| FR-012 | 移出与重新启用文档库 | P0 | 默认停用而非清除；明确不影响原文件 |
| FR-013 | 异常与诊断 | P0 | 显示缺失、离线、权限和索引错误，不用“空列表”掩盖失败 |
| FR-014 | 手动重新定位缺失文档 | P1 | 用户确认后绑定到同一文档库内的新路径；冲突时拒绝合并 |
| FR-015 | 明暗主题、界面状态记忆 | P1 | 首版至少提供一个可用主题；主题切换不阻塞核心验收 |
| FR-016 | 从搜索命中定位到行 | P1 | 仅在实际安装的 Notepad3 版本验证通过后启用 |

补充规则：

- 添加文档库只登记文件，不复制、移动或改写它们。
- 首版不提供“全盘扫描”、拖入库外文件自动复制等隐式导入操作。
- 重名新建一律失败并提示，不自动覆盖，也不静默改成另一个文件名。
- 删除标签只移除标签及关联；不得删除文档记录或文件。
- 最近打开表示“启动请求成功”，不是编辑器已完成加载或保存的证明。
- 搜索默认只包含在线、启用、符合管理规则且未缺失的文档。
- 未索引文件仍参与文件名搜索，正文搜索明确显示未覆盖数量。
- 0.2.0已实现手动重新定位：旧记录保留，用户可确认新路径；仅对无人工信息的自动登记占位允许明确确认合并。不承诺自动保留全部外部移动关系。
- 0.4.0支持运行期间可验证的同库直接单文件改名/移动自动关联，保留原ID与人工信息；必须具备新鲜完整事件和真实身份联合证明。跨库、关闭期间、整目录、链式/冲突和未知身份仍安全降级，不宣称全场景跟踪。

## 5. 非目标

- 不修改 Notepad3 源码，不嵌入其窗口，不替换系统记事本关联。
- 不读取编辑器内存，不管理未保存标签页，不强制编辑器自动保存。
- 不做富文本编辑、插件平台、云账号、同步、多人协作、AI 问答。
- 不自动解析 PDF、Word 等二进制文档。
- 首版不支持 UNC/网络共享、云端占位文件和可移动盘作为正式文档库。
- 不保证管理器关闭期间的任意移动都能无歧义追踪。

## 6. 关键用户流程

### 6.1 首次使用

选择 Notepad3 → 添加文档库 → 确认扩展名和排除项 → 扫描 → 查看结果及异常。

Notepad3 未配置时仍可浏览和搜索；点击编辑时引导配置，不阻断其他功能。

### 6.2 创建与编辑

选择库内现有文件夹 → 输入文件名和类型 → 选择空白或内置模板并预览 → 排他创建文件 → 登记 → 启动 Notepad3。

若登记失败，显示已创建的路径并安排扫描补登记，不回滚删除文件。若启动失败，文件依然存在，可重试打开。

0.7.0模板只新建文件，不应用到已有正文。模板变量单遍白名单替换；日期按实际创建时间生成。创建后的写入、刷新或取消失败保留文件并提示，不自动重试创建或启动编辑器。

### 6.3 保存后搜索

Notepad3 保存 → 管理器检测文件变化 → 稳定读取 → 更新正文索引 → 搜索命中新内容。

明确区分“等待索引”和“没有命中”；不得将尚未完成索引的结果描述为全库完整结果。

### 6.4 离线与缺失

根目录不可用 → 显示库离线，保留标签和收藏。根目录在线、文件确认不存在 → 标记缺失，保留记录并提供检查路径入口。

## 7. 非功能目标

- 安全：除用户明确的新建操作外，不写入已有正文。
- 响应：扫描、索引、预览和数据库操作不阻塞界面线程。
- 可恢复：索引损坏可重建；管理信息损坏必须走备份恢复，不能冒充“全部可重建”。
- 可解释：任何跳过、截断、异常和搜索范围限制对用户可见。
- 可维护：将编辑器、文件系统和数据库依赖隔离，核心规则可自动化测试。
- 可访问：键盘导航、高 DPI、文字缩放和清晰焦点反馈进入验收。
- 分发：交付包含运行依赖的 Windows x64 目录包，并在未安装 Python/开发工具的测试环境验收；不能以开发机运行正常代替发布包验收。

性能初值及测试环境详见 [开发与验收](06-delivery-and-acceptance.md)。
