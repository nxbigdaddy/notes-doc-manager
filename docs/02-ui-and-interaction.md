# 02 — 界面与交互

## 1. 主窗口信息架构

采用 wxPython 原生风格三栏窗口，不模拟 Notepad3 的编辑区域，不使用 WebView 或网页前端。

| 区域 | 内容 |
|---|---|
| 顶栏 | 搜索框、新建、添加文档库、刷新、设置 |
| 左栏 | 所有文档、收藏、最近打开、文档库与文件夹树、标签 |
| 中栏 | 筛选摘要、文档列表、分页或增量加载、结果总数 |
| 右栏 | 只读预览、标签、收藏、完整路径、编码、文件状态、编辑按钮 |
| 状态栏 | 扫描进度、待索引数量、失败数量、库连接状态 |

布局初值：左栏约 220 DIP，中栏最小 320 DIP，右栏最小 300 DIP；均可调整。窄窗口时允许折叠预览，不强制让用户横向滚动整个页面。

## 2. 文档列表

默认按文件修改时间倒序，同时间以文档 ID 稳定排序。

“最近打开”视图例外：按管理器发出打开请求的时间倒序，在当前元数据筛选范围内取最近100条；不把文件修改时间冒充打开时间。

字段：

- 文件名及扩展名。
- 文档库与相对目录；同名文件必须能区分。
- 修改时间、大小。
- 标签、收藏标记。
- 待索引、缺失、读取失败等状态。

采用虚拟化列表，不一次构造全部文档的可视控件。第一版不承诺复杂文件夹树的跨库拖放。

交互：

- 单击：更新右侧预览。
- 双击 / 列表焦点下 Enter：用 Notepad3 打开。
- 右键：编辑、复制路径、打开所在目录、管理标签、收藏。
- 缺失记录：禁用编辑，提供检查原路径及重新定位入口。
- 快速切换选择时取消旧预览请求，迟到的结果不得覆盖当前文档。

## 3. 搜索

### 3.1 查询入口

- 模式：全部 / 文件名 / 正文，默认全部。
- 文本：首版按**完整输入的字面子串**查询，不把空格自动解释成 AND，不开放正则和 FTS 表达式。
- 筛选：当前文档库或所有库、文件夹子树、收藏、标签。
- 多标签选择：默认必须同时具备所有选中标签，界面写明“同时包含”。
- 清空查询：返回当前筛选下的正常列表。
- 默认忽略拉丁字母大小写，不做简繁转换、拼音或语义扩展。

### 3.2 结果展示

- 命中文件名优先，其次正文；组内按修改时间、文档 ID 稳定排序。
- 每个文档只出现一次，显示命中位置类型和首个正文摘要。
- 首版每页 100 条，支持下一页；短词查询显示可取消进度。
- 展示“正文已覆盖 X 个，待处理/跳过 Y 个”，文件名搜索不受正文索引状态限制。
- 查询中、查询超时、索引不完整、完全无匹配使用不同提示。
- 搜索词高亮只生成文本格式，不把文件内容当作 HTML。
- 从摘要跳转到行是 P1；文件已变化时提示位置可能偏移，并退化为普通打开。

## 4. 预览

- 仅显示已保存内容，不显示编辑器未保存状态。
- 显示文件完整路径、解码方式和文件修改时间。
- 默认最多读取 256 KiB 源字节进行预览；截断时提示“仅预览开头部分”。
- 自动换行可切换，首版不提供正文编辑和保存按钮。
- `.md` 首版作为纯文本；不加载链接、图片、脚本或网络资源。
- 编码无法确认时提供“选择编码”；选择改变预览和索引策略，不转码原文件。
- 读取失败不继续展示无标识的旧内容；清空或明确标记缓存已过期。

## 5. 对话框与设置

### 添加文档库

目录、显示名称、扩展名白名单、排除目录。选择重叠目录时指出已存在的文档库，而非偷偷合并。

### 新建文档

文档库、库内现有文件夹、文件名、类型。显示最终绝对路径。只接受单个文件名，不允许通过名称输入路径跳转。

无权限、重名、路径越界均在创建失败后显示具体原因；预检查通过也不能替代创建时的排他校验。

### 标签管理

新建、改名、删除标签；标签名去除首尾空白，不允许空标签。删除时提示影响多少个文档关联，不涉及文件删除。

### 设置页

1. 编辑器：Notepad3 绝对路径、文件版本展示、手动测试打开。
2. 文档库：规则、停用/启用、刷新、异常详情。
3. 搜索：索引覆盖情况、重建、超限说明。
4. 数据：应用数据位置、导出、恢复、备份目录。
5. 外观：字体与布局；主题切换为 P1。
6. 诊断：日志位置、生成脱敏诊断包；不自动上传。

### 恢复管理信息

选择备份 → 校验格式及版本 → 展示记录数量、原路径和不可用路径 → 明确说明替换管理信息、不恢复正文 → 备份当前状态 → 确认恢复。

导入的外部编辑器路径默认不启用，用户重新确认后才能启动。

## 6. 快捷键

| 快捷键 | 行为 |
|---|---|
| Ctrl+F | 聚焦搜索框 |
| Ctrl+P | 快速打开小窗（文件名/最近打开） |
| Ctrl+N | 新建文档 |
| F5 | 刷新当前文档库；所有文档视图下刷新所有启用库 |
| Enter | 列表焦点下编辑；搜索框焦点下立即提交查询 |
| Esc | 优先关闭弹窗，其次取消当前搜索；不清除全部筛选 |

不绑定 Delete 删除文件，不劫持系统全局快捷键。快捷键在文本输入控件内遵循正常编辑习惯。

## 7. 状态文案

| 状态 | 提示示例 |
|---|---|
| 无文档库 | “添加一个文件夹开始管理，文件不会被搬动。” |
| 扫描中 | “已发现 320 个文件，正文索引仍在处理中。” |
| 短词查询 | “正在扫描已索引正文，可缩小文档库范围加快搜索。” |
| 索引不完整 | “12 个文件尚未完成正文索引，本次正文结果可能不完整。” |
| 根目录离线 | “文档库路径当前不可访问，标签和收藏已保留。” |
| 文件缺失 | “原路径未找到文件，可能已被移动或删除。” |
| 编码待确认 | “无法可靠解码，请选择编码；不会修改原文件。” |
| 打开请求已发出 | “已请求 Notepad3 打开文件。”不能写成“保存成功” |
| 新建后启动失败 | “文件已创建，但编辑器启动失败，可重试。” |
| 搜索取消/超时 | “查询未完成”，不显示为“共 0 条” |

## 8. 无障碍与窗口行为

- 首发单实例；再次启动只激活已有窗口，默认关闭窗口即退出，不驻留托盘。
- 所有按钮提供文字或可访问名称，状态不得只依赖颜色。
- 验证 100%、150%、200% DPI 和键盘 Tab 顺序。
- 保存窗口位置时检查显示器是否仍存在，避免窗口恢复到屏幕外。

## 9. wxPython 控件与事件方案

以下是本项目的控件映射设计，具体 API 和外观在 M1 验证；列表与预览的官方能力见 [07](07-decisions-and-references.md) 的 S12、S13。

| 区域 | 控件方案 | 实现约束 |
|---|---|---|
| 主窗口 / 分栏 | `wx.Frame`、`wx.Panel`、嵌套 `wx.SplitterWindow`、Sizer | 用布局管理器和 DIP 转换，不硬编码整窗像素坐标 |
| 文档库与文件夹 | `wx.TreeCtrl` | 按需展开；磁盘枚举在后台，不在展开事件中同步遍历 |
| 文档列表 | `wx.ListCtrl`，`wx.LC_REPORT \| wx.LC_VIRTUAL` | 回调只读取当前页缓存，绝不在 `OnGetItemText` 中访问磁盘或数据库 |
| 搜索 | `wx.SearchCtrl`、筛选控件 | 防抖、请求代际和取消由 Presenter 协调 |
| 只读预览 | `wx.stc.StyledTextCtrl` | 始终保持用户只读；由程序加载缓存文本，不使用控件直接读写文件 |
| 对话框 | `wx.Dialog`、文件/目录选择器 | 选择完成后仍按业务层规则校验路径 |
| 状态 / 快捷键 | `wx.StatusBar`、进度控件、`wx.AcceleratorTable` | 输入框内不抢占正常文本编辑快捷键 |

补充边界：

- wxPython 的虚拟列表按需取行，不等于自动完成数据库分页；应用维护当前页、预取缓存和稳定文档 ID，首版搜索仍每页 100 条。
- 预览控件仅用于显示、复制和高亮，不新增“内置编辑器”需求。使用其文本组件不意味着嵌入或复用 Notepad3 进程。
- 预览使用 UTF-8 位置语义时，必须把 Python 字符位置转换为控件字节位置；中文、emoji 和规范化后的高亮偏移纳入测试。
- 所有控件创建、销毁和修改都在 GUI 主线程；后台仅提交结果，经 `wx.CallAfter` 回到界面 [S3]。回调落地前检查窗口生命周期和请求代际。
- 首版优先使用系统可读的默认主题；不同系统和 wxPython 版本的深色控件覆盖不预先承诺，主题切换保持 P1。
- 单实例检测和激活放入 Windows 平台适配层：先取得实例所有权，再允许数据库写入；第二实例只发送无正文数据的激活信号，不启动扫描。冻结发布包必须复测该流程。

## 10. 0.6.0 快速打开

- 文件菜单或Ctrl+P打开唯一的小窗，再次调用只聚焦已有窗口。
- 200ms防抖，最多20条文件名结果；纯空白展示最近打开，明确说明不继承主列表筛选。
- 上下选择，Enter/双击请求打开；失败、未配置编辑器和不完整查询在小窗内显示，不把“没有结果”冒充查完。
- Esc/关闭取消本通道查询及尚未执行的打开请求；迟到回调不得更新关闭窗口。
- 工具菜单可选全局Ctrl+Alt+N，默认关闭。注册冲突提示且不反复重试；机器偏好不会随恢复自动激活。
- 注销失败不虚报已关闭，提示退出释放；程序退出时抑制后续回调并清理注册。
- 自动测试只使用假注册后端；已验证消息路由，不等于真实系统快捷键交互/冲突验收。

## 11. 0.7.0 内置文档模板

- Ctrl+N或“新建”对话框提供空白、会议纪要、每日记录、问题排查四项；默认空白，原有空文件操作不变。
- 模板正文只读预览，200ms防抖；模板列表/预览异步加载，错误可见，旧请求结果不能覆盖新选择。预览成功前不允许提交。
- 默认文件名建议扩展名必须属于当前库；切换模板不覆盖用户已编辑的文件名。模板不限制只能使用`.md`。
- 明示“日期/时间以实际创建时为准”。预览跨过午夜后，真正新建按创建当天重新生成，不把旧预览直接写入。
- 重名明确失败、不覆盖也不自动换名。写入中途失败则显示已创建文件仍保留；不自动删除、重试创建或打开编辑器。
- 不提供自定义模板路径、模板脚本、模板编辑器或已有文档套用模板；所有新建内容仍交给Notepad3后续编辑。

## 12. 0.8.0 智能列表

- 左侧独立智能列表分组；工具菜单提供新建、保存当前筛选、编辑当前列表、删除。列表项右键同样提供编辑/删除。
- 表单可组合名字、搜索词、搜索范围、单库、相对文件夹、多标签AND、收藏、最近及包含缺失记录；显示首次保存保护备份及升级格式后需要0.8+的提醒。
- 活动保存视图锁定主搜索词/模式/包含缺失控件，明确显示保存范围；选择普通导航后再使用临时搜索，避免控件内容与实际查询不一致。
- 编辑时失效的库/标签显示原ID并保持选择，不自动变为“全部库”或删掉标签；用户明确取消失效条件或选择有效替代后才保存。
- 列表删除、失效或读取失败后保持该活动范围并清空旧结果/预览，显示原因；不能自动回到所有文档。迟到查询不覆盖已切换视图。
- 删除需确认且明确不删文档。恢复确认显示智能列表数量；旧format1备份说明会清空当前列表，保护备份仍先执行。
