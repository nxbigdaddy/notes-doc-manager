# 17 — 可丢弃索引连接缓存建议值评估（2026-09-21）

> 本轮为非生产可行性评估。`src`、版本、运行库及0.8.3发行包冻结，不据一次计时直接发布参数调整。

## 1. 唯一变量

上一轮观察到耗时更多落在缓存写入、事务和关闭路径，逐ID元数据读取候选已否决，不重复该候选。

本轮只在隔离服务的连接工厂外加实验包装：原连接创建完成后，仅对`search-v2.db`写连接设置`PRAGMA cache_size=-8192`。原组保留原配置，候选组使用8MiB建议值。

该值是SQLite会话内页缓存的**建议额度，不是整个进程的内存硬上限**；当前连接关闭后不持久化到文档或管理配置。参考SQLite官方PRAGMA说明：`https://www.sqlite.org/pragma.html#pragma_cache_size`。

不改以下内容：

- 元数据FULL/搜索缓存NORMAL同步级别、WAL模式、5秒busy timeout、自动checkpoint。
- 事务/回滚/代际校验、50条批次、编码与文件身份校验。
- 不启用anchor，不显式设置`cache_spill`；其查询返回的有效阈值可能随缓存建议值改变，不能错误要求数值完全一样。
- 不读取真实文档、不启动GUI或编辑器、不下载/升级SQLite。

## 2. 先执行的安全门槛

独立agent只新增隔离测试，不改生产代码：

1. 连接重开恢复默认，元数据连接未被调参；同步/日志/超时等规则保持。
2. ready/stale代际、缓存写锁BUSY回滚和解除锁后刷新重试不变，真实损坏仍降级。
3. 源文件/标签等管理信息不变。
4. 取消仍遵守“已完成读取可提交、未完成核验不得记成功”；短操作在批次结束或失败后可以取得门锁，不以耗时阈值代替并发语义。

任何失败先停止，不为提速降低安全门槛。

- 使用同一诊断脚本和语料，保持生产源码、runtime/native/依赖指纹一致。
- 记录完整文件名/正文覆盖、源文件hash、实际连接配置、进程工作集/峰值工作集，以及SQL调用分类时间。
- 进程内存测量只代表CLI，不包括wx GUI，也不是SQLite分配器精确用量。
- 指标包含诊断包装、缓存和机器负载影响；不与旧报告硬算提速，不外推500MiB、p95或正式Win11验收。
- 不自动循环重跑。差异小、结果相互矛盾、内存明显恶化或语义/指纹失败，则不采用。

如仅显示值得进一步验证的信号，也不能立即修改生产默认值；先明确更大样本、真实UI短操作及内存预算所需证据。本轮结束后记录go/no-go及尚缺项，避免每小时重复同一实验。
