## 1. 设计结论

开发独立的 Windows 本地文档管理器，继续使用用户现有的 Notepad3 编辑文件，不修改、嵌入或重新打包 Notepad3。

- **文件系统**保存正文，是文档内容的权威来源。
- **管理器**负责文档库、标签、收藏、预览和搜索。
- **Notepad3**负责编辑，只通过外部进程参数集成。
- **本地数据库**保存管理信息；正文搜索缓存可重建，不是唯一正文副本。
- 第一版不提供已有文件的移动、重命名、删除和正文写回，降低误操作风险。

已选技术路线：**Python + wxPython + SQLite**。具体采用标准库 `sqlite3`、FTS5 搜索、`watchdog` 文件监听和 PyInstaller 目录打包；UI 使用原生风格控件，不引入网页前端。技术依据和待验证项见 [决策与资料](07-decisions-and-references.md)。

最初候选为CPython3.13，前几轮实际采用本机3.14.0/SQLite3.50.4。0.5.0改为**项目私有CPython3.14.7 + 官网SQLite3.53.4 x64 DLL + wxPython4.2.5**，原因和校验见[运行时维护](10-startup-recovery.md)。不修改系统安装，依赖有哈希锁文件；冻结包也核对实际引擎和DLL哈希。

## 3. 已明确与暂定

### 用户已明确

1. Notepad3 的编辑体验已基本满足需要。
2. 希望统一管理相关文档。
3. 最初先完成设计；2026-09-15 用户已授权开始实现、多 agent 同时工作、持续自主迭代。
4. 采用 Python 方案 A：wxPython 原生风格 GUI + SQLite，独立于 Notepad3。

### 本次采用的设计假设

1. 继续按独立管理端实现，不修改 Notepad3；文件管理和编辑仍分工独立。
2. 面向个人、单机、Windows 使用，不含团队协作和跨平台。
3. 正式发布验收平台暂定 Windows 11 x64、本地 NTFS；已检测到的本机 Windows 10 Pro 22H2 x64 纳入兼容性验证。两者均尚未通过应用测试，不因换成 Python 就自动宣称兼容或处于上游支持期。
4. 默认管理 `.txt`、`.md` 文件；其他纯文本扩展名由用户显式添加。
5. 文档可分布在多个不重叠的目录，无需搬入统一专有目录。
6. 首轮规模目标为 10,000 个文档、可索引正文合计不超过 500 MiB，需原型测量。

这些是供评审的默认值，不是已经收集到的真实用户数据。

### 已有环境检查的边界

2026-09-15 最初只读检查确认本机为 Windows 10 Pro 22H2 x64，Notepad3 为 7.26.426.1。随后按开发授权独立验证了 Python/wxPython、PyPI 安装、FTS5 与 PyInstaller 源码/冻结入口；结果见迭代日志。没有修改系统 Python、Notepad3 配置或用户正文。

## 4. 首版完成定义

用户可以添加目录、浏览与预览、新建并调用 Notepad3、添加标签与收藏、搜索文件名和已保存正文，并能备份和恢复管理信息。

同时必须满足：

- 重新打开管理器后，标签和收藏保留。
- 外部保存后最终更新索引；未保存文字不属于管理范围。
- 离线、无权限、读取失败和文件缺失有不同提示，不自动抹除标签。
- 中文短词和特殊字符查询有明确语义，不静默漏掉不支持的搜索范围。
- 现有正文不因扫描、预览、搜索、数据库恢复而被修改。
- 明确说明“管理信息备份”不等于“文档正文备份”。
