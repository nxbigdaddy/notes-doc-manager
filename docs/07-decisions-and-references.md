# 07 — 决策、风险与参考资料

> 更新日期：2026-09-16；版本 v0.8。已自主迭代至0.6.0快速打开候选；发布前仍须完成未验证边界。

## 1. 架构决策记录

### ADR-001：独立管理器，不 fork Notepad3

- 状态：已随用户选择的独立 Python 管理器路线确定；集成细节待验证。
- 原因：现有编辑体验已满足需要，当前缺口主要是管理。
- 结果：进程参数集成；不复用上游界面或编辑器核心。
- 代价：无法可靠获知所有未保存状态和窗口生命周期。
- 重审条件：出现必须与编辑器内部文档状态同步且外部集成无法满足的需求。

### ADR-002：本地 Windows + WPF（历史决策，已被 ADR-009 替代）

- 状态：已废止，不再作为实施依据。
- 历史：v0.1 暂选 C# / .NET 10 / WPF；2026-09-15 用户要求切换 Python，随后选择方案 A。
- 替代：使用 Python + wxPython + SQLite，详见 ADR-009。此前与旧工具链有关的环境检查只保留为历史事实，不构成 Python 环境验收。
- 本文保留这一记录解释变更原因；当前设计不再要求 WPF、XAML、MVVM Toolkit、Microsoft.Data.Sqlite、NuGet 或 MSBuild。

### ADR-003：正文保留为普通文件

- 状态：建议采用，核心原则。
- 结果：正文不迁入专有存储；数据库保管逻辑标签和缓存。
- 代价：需面对文件外部变化、路径身份和索引最终一致性。

### ADR-004：元数据与搜索库分离

- 状态：建议采用。
- 原因：区分不可重建的标签数据和可丢弃的正文索引。
- 代价：跨库不能假设原子提交，需要 UUID、generation 校验和补偿。
- 重审条件：实现复杂度显著超过收益；若合库，仍需保留“只重建搜索、不删除标签”的能力。

### ADR-005：FTS5 trigram 与短词回退

- 状态：须在 M1 验证后定案。
- 原因：先支持可解释的字面子串，不引入独立搜索服务。
- 代价：1～2 字查询可能全扫描；需要严格字面转义和覆盖提示。
- 重审条件：真实中文数据下结果正确性或性能不合格；可评估 bigram 辅助索引，不默认切换架构。

### ADR-006：首版不整理已有物理文件

- 状态：建议采用。
- 结果：已有文件的重命名、移动、删除留到后续；首版以标签、收藏和外部打开为主。
- 原因：无法可靠获知 Notepad3 的未保存状态，避免首次交付承担高风险文件操作。

### ADR-007：不猜测离线移动的身份

- 状态：建议采用。
- 结果：路径不变保留标签；可靠同库 rename 尝试保留；其他情况保留旧记录待确认。
- 代价：用户可能需手动重新定位；不得宣称“任意移动标签永不丢”。

### ADR-008：不捆绑编辑器，不改变系统关联

- 状态：建议采用。
- 原因：尊重现有配置，缩小分发和兼容边界。
- 结果：配置路径，记录并测试版本；无自动安装、替换记事本和强制升级。

### ADR-009：Python + wxPython 原生风格 GUI + SQLite

- 状态：**用户已确认主技术路线**。
- 原因：用户选择 Python 实现，并在 GUI 候选中明确采用方案 A。
- 结果：wxPython 控件、MVP 分层、标准库 sqlite3、watchdog 监听、subprocess 调用编辑器；不引入 Qt 或网页前端。
- 版本初值：CPython 3.13 x64 标准构建、wxPython 4.2 系列。此组合不是“最新版本”声明；是否具备可用 wheel、支持状态与打包兼容性在 M1 验证后锁定。
- 代价：需要验证原生控件高 DPI、UI 线程、Unicode 偏移、SQLite 编译能力和冻结打包；不能仅凭 Python 代码可运行就认定可发布。
- 平台：保留 Windows 11 x64 正式验收建议，并纳入已知的本机 Windows 10 Pro 22H2 x64 兼容验证；不扩展到 macOS/Linux。

### ADR-010：GUI 主线程 + 受限后台线程 + 显式连接归属

- 状态：实施建议，M1/M3 验证。
- 结果：wx 控件仅在 GUI 线程访问，后台经 `wx.CallAfter` 返回；写线程独占写连接，读任务独立连接，保留 sqlite3 线程检查。
- 代价：需要协作取消、请求代际和关闭协调；工作线程不能被当作纯 Python CPU 工作的无限并行加速。
- 不采用：在事件里同步扫描、跨线程共用连接、无限事件/任务积压、强杀线程替代事务收尾。

### ADR-011：PyInstaller 目录包，先验证冻结应用

- 状态：实施建议，M1 最小验证、M4 发布验收。
- 结果：先交付 Windows x64 onedir GUI 包，冻结后重测 SQLite FTS5、编码、wx.stc、资源、监听和 Notepad3 调用。
- 代价：发布包可能包含较多原生依赖；需要检查 DLL 搜索环境和干净机器运行，不能保证自动比旧路线更轻。
- 不采用：首版 onefile 优化、运行时 pip 安装、捆绑 Notepad3、默认自动更新。

### ADR-012：手动重新定位允许确认吸收无人工信息占位

- 状态：0.2.0实施，已纳入服务和GUI测试。
- 原因：外部移动后的目标通常已自动登记，绝对禁止目标冲突会使手动重新定位难以使用。
- 边界：只允许真实缺失的原记录、同库合规文件；目标无任何人工信息时需额外明确确认，事务中重复检查。有人工信息的目标拒绝，不自动猜测同名/同内容身份。
- 结果：保留原ID、标签、收藏和编码，不移动或改写任何正文。自动可靠rename跟踪仍是独立未完成项。

### ADR-013：内部维护时间和快照所有权持久化

- 状态：0.2.0实施。
- 自动备份：UTC自然日加管理信息指纹；保留最近7次登记成功的自建快照，保护快照不轮换，时钟回拨不误删最新产物。
- 内容核验：仅完整成功才保存墙钟时间；取消/失败延迟采用单调时钟，启动时重新评估到期。
- 读取重试：同代际最多5次，租约token拒绝迟到结果；真实新代际才重置，不用重新扫描无限重开同一组失败。

### ADR-014：隔离的external-content搜索缓存

- 状态：0.3.0实施。
- 原因：减少重复正文存储；同时旧exe不认识触发器维护方式，不能对原search.db直接原地换结构。
- 结果：新search-v2.db独立版本；旧缓存不改。首次升级重新读取正文，先提升全局文档代际，避免旧缓存以同代际复活。
- 代价：升级期保留新旧缓存占用；首次重建耗时。触发器、迁移、中断、覆盖、代际和查询语义均需真实SQLite回归。

### ADR-015：未解释的大集实验不进入生产扫描路径

- 状态：0.3.0保守决策。
- 原因：空闲缓存锚连接小样本通过，但一次大集实验退出原因未明。
- 结果：保留可显式调用的实验API与测试，应用默认扫描不使用；按已完成的无锚大集结果报告，不为达到性能数字牺牲可解释性。

### ADR-016：事件与实测身份联合证明直接文件移动

- 状态：0.4.0实施。
- 原因：仅按名字/内容或永久文件号推断身份都不可靠；Windows文件编号可能复用，创建时间也不能单独作为证明。
- 结果：短时完整单文件事件、既有设备/编号/出生时间基线、旧路径缺失、目标实测及无人工冲突联合成立后才更新管理关联。
- 边界：不做目录/链式推理、跨库推理、离线历史推理和硬链接归并；不可靠时保留缺失记录。实际文件移动仍由用户/其他工具完成。

### ADR-017：已保存根目录每次使用前重新验证卷边界

- 状态：0.4.0安全修复。
- 原因：首次添加时固定NTFS并不意味着后续盘符不会重映射为不支持的卷。
- 结果：路径IO、订阅之前验证卷；既有根的重复判断用规范路径字符串，不因添加新库而探测旧盘。身份未知与不支持卷不扩大访问范围。

### ADR-018：坏库恢复独立于正常Store初始化

- 状态：0.5.0实施。
- 原因：让Store先启动可能把缺表/空主库误当新库，且正常界面可能根本打不开。
- 结果：单实例下先检查与续作；只在明确确认和指纹匹配时，从验证后的逻辑记录创建新库，保全旧main/sidecars，journal决定完成/回退/阻止未知状态。
- 代价：保留故障会话占用磁盘，无法判定的外部修改需人工处理；不声称能防御所有同权限竞争。

### ADR-019：使用官方修复版SQLite的项目私有运行时

- 状态：0.5.0实施。
- 依据：SQLite官方WAL-reset问题及修复版本；Python补丁号不保证其附带的SQLite已修复。
- 结果：私有CPython3.14.7 + 官网3.53.4 DLL，归档固定哈希/官网SHA3/架构/实际版本验证；保留原件，不改系统。详见10。
- 不推断：这不证明此前锚连接退出由该问题导致；锚连接仍禁用。

### ADR-020：快速打开独立取消与短动作执行

- 状态：0.6.0实施。
- 原因：共用取消令牌会使两个窗口互相打断；把打开请求排在整库扫描之后不符合快速打开用途。
- 结果：main/quick独立令牌、快捷查询和短动作独立容量；Store门锁保护最终文档快照与请求，不改变原文件。
- 风险控制：初始列表不是权威路径，发出请求前重新读取并检查；关闭取消排队Future，已启动的外部编辑器不强制关闭。

### ADR-021：全局快捷键必须选择启用

- 状态：0.6.0实施。
- 结果：固定Ctrl+Alt+N初版默认关闭、冲突失败不抢占、成功注册后保存；不创建自启动或驻留任务，恢复不导入该机器设置。
- 验证边界：假后端和真实本窗口消息路由通过，不把它们称为用户桌面实际快捷键验收。

## 2. 风险清单

| 风险 | 影响 | 应对 | 验证阶段 |
|---|---|---|---|
| 中文短词搜索慢 | 常用查询体验差 | 有界后台扫描、进度和取消，必要时新增索引方案 | M1/M3 |
| 监听事件漏失 | 搜索不是最新 | dirty 标记、补扫、哈希核验 | M3 |
| 外部移动无法关联 | 标签与路径脱节 | 保留缺失记录、不猜测、手动重新定位 | M3/P1 |
| 原子替换误判为删除 | 标签丢失或重复记录 | 延迟验证、路径逻辑身份、事件风暴测试 | M1/M3 |
| 编码误识别 | 乱码或搜索漏命中 | 严格解码、用户 override、范围提示 | M1/M3 |
| 正文缓存泄露 | 本地隐私暴露 | 明示缓存含正文、用户目录权限、无自动上传 | M4 |
| 元数据损坏 | 标签收藏丢失 | 一致性备份、导出、恢复演练，不静默重建 | M1/M4 |
| Notepad3 版本差异 | 打不开或定位不准 | 基础参数最小化、实际版本矩阵、P1 降级 | M1/M4 |
| 大量后台任务 | UI 卡顿/占用高 | 有界队列、串行写、限速读取、可取消 | M3/M4 |
| 数据库迁移中断 | 应用无法启动 | 保护备份、事务迁移、恢复阶段标记 | M4 |
| 用户误解备份范围 | 误以为正文可恢复 | 所有导出恢复界面强调“不含正文” | M2/M4 |
| Python/wxPython wheel 不匹配 | 安装失败或触发复杂本地编译 | 固定 x64 标准构建，先验证二进制可用性，再锁版 | M1 |
| wx 回调操作已销毁窗口 | 退出崩溃或错误内容回填 | 请求代际、closing 状态、批量回调及协作关闭 | M1/M3 |
| sqlite3 连接跨线程/事务误用 | 运行异常或数据不一致 | 显式连接归属、保留线程保护、真实事务测试 | M1/M3 |
| 冻结包缺失模块或 DLL | 开发可用、发布不可用 | 最小包尽早验证，检查编码/FTS5/资源和外部进程环境 | M1/M4 |
| Windows 10 兼容性/维护边界 | 本机可开发但正式支持结论不清 | 单独记录实测及上游支持，不把选 Python 当作兼容保证 | M1/M4 |

## 3. 待确认事项

主技术路线已确定，不再作为待选项。以下实施问题在开发前确认：

1. 已知本机 Windows 10 Pro 22H2 x64 是否必须纳入正式发布支持，而不只是兼容验证？Windows 11 测试环境如何提供？是否需要 ARM64？
2. 目前文档数量、总体积、主要扩展名和典型编码是什么？
3. 文档位于本地固定盘，还是含网络盘、同步目录、移动硬盘？
4. 已检测到 Notepad3 7.26.426.1；还需确认安装/便携习惯、窗口复用设置及实际命令行行为。
5. “统一管理”的优先级更偏向正文搜索、标签，还是物理移动整理？
6. 是否需要首版就提供手动重新定位和 Markdown 渲染？
7. 产品名称、图标、主题和分发范围是什么？
8. 管理信息备份应导出到什么位置，是否需要加密备份？
9. 本机可用于本项目的 CPython 版本、架构、pip、wheel 来源和 PyPI 连通性是否满足要求？wxPython 与打包工具尚未检查。
