# 06 — 开发计划与验收

## 1. 当前阶段

用户已再次授权持续迭代。当前为 **0.6.0 快速打开版**，已交付日常管理、限定文件移动关联、安全恢复和快速打开；没有克隆/修改 Notepad3 或用户真实文档。部分性能与外部正式验收仍保留；下一阶段按已讨论的模板、智能列表分版本推进。

v0.2 确定 Python + wxPython + SQLite；v0.3 已在本机 Windows 10 Pro 22H2 x64 完成源码和冻结包基础验证。真实测试结果、未通过的性能指标、未执行的外部平台验收见 [迭代日志](09-iteration-log.md)。

以下里程碑仍作为目标，不承诺日历工期；功能测试通过不等于所有验收条目或 M4 已完成。

## 4. 测试层次

- 单元：用 pytest 测试文件名与路径规则、状态迁移、查询规范化、FTS 转义、代际匹配，使用临时目录 fixture。
- SQLite 集成：真实 FTS5 能力、事务、索引重建、迁移、导出恢复。
- 文件系统集成：临时隔离目录、实际文件监听、原子替换、权限和锁定。
- 故障注入：入队后、元数据提交后、索引提交后、备份切换中断等关键位置。
- UI 冒烟：wxPython 主线程规则、虚拟列表缓存、核心键盘路径、进度、空状态、预览竞态、销毁后回调和退出收尾；Presenter 单测不依赖真实窗口。
- 编辑器兼容：使用实际 Notepad3 发布版本手工及自动化测试，记录版本和配置。
- 发布包冒烟：PyInstaller onedir 在未安装 Python/开发工具的 Windows 11 x64 测试；本机 Windows 10 Pro 22H2 x64 另记兼容结论，不能相互替代。
- 静态检查：ruff 格式与规则检查；锁文件一致性、资源/迁移 SQL 收集和依赖许可清单检查。

测试只在专用临时目录和生成数据上进行，破坏性场景不得使用用户真实文档。

## 5. 非破坏性验证

对测试文档集记录文件路径、大小、哈希；执行扫描、预览、搜索、标签操作和管理信息恢复后核对。

- 除显式新建文件外，已有文件正文哈希必须保持不变。
- 读取可能影响文件系统访问时间，不以“所有文件系统元信息绝不改变”作承诺。
- 标签删除、停用库和恢复元数据均不得导致正文文件删除。
- 所有失败恢复都要验证旧文件与保护备份仍在，而不只验证应用能启动。

## 6. 性能目标（待测）

正式基准环境暂定：Windows 11 x64、4 核以上 CPU、16 GiB RAM、本地 SSD；本机 Windows 10 Pro 22H2 x64 作为额外兼容样本。记录实际机器型号、OS、CPython、wxPython/wxWidgets、SQLite、watchdog、PyInstaller、Notepad3 版本，以及源码/冻结入口，不能混用两组结果。

固定测试集：10,000 个文档、可索引源正文合计 500 MiB，包含中英文与边界字符，单独添加跳过/编码待确认样例。数据生成方式和随机种子在实施时入库。

| 指标 | 初始目标 | 测量口径 |
|---|---|---|
| 已有库启动 | 3 秒内可交互 | 进程启动到列表可操作，完整核对可继续后台运行 |
| 文件名查询 | p95 ≤ 200 ms | 至少 100 次暖查询，后台无大量扫描，首个结果页完成 |
| ≥3 字符正文查询 | p95 ≤ 500 ms | 同上，不含输入防抖时间 |
| 1～2 字符正文查询 | p95 ≤ 3 秒 | 完整扫描允许缓存正文范围；超时不得伪称完整 |
| 普通文本预览 | p95 ≤ 200 ms | 文件 ≤256 KiB，本地可读，从选择到显示 |
| 保存到正文可搜 | 95% ≤ 3 秒 | 小文件、低事件压力、无锁；从文件写入结束计时 |
| 全量索引 | ≤120 秒 | 固定 500 MiB 测试集，记录首次/重建两种结果 |
| 常驻内存 | 空闲工作集目标 ≤200 MiB | 索引结束且 UI 稳定；峰值单独记录 |

这些不是既有实测成绩。若短词查询、内存或索引时间达不到目标，M1/M3 给出实测与方案调整，不能隐藏范围限制来“达标”。

技术切换后保留上述数值作为初始目标，不把原方案预期当作 Python 实测。补充记录发布目录体积、冷启动/暖启动和索引峰值工作集；不预先承诺 Python 比原方案更快或更小。

## 7. 发布门槛

1. P0 功能和 AT 中对应首版测试全部通过。
2. 中文与特殊路径、原子保存、库离线、备份恢复、索引损坏已在真实 Windows 环境验证。
3. 新建以外的文件哈希不变验证通过。
4. 无数据丢失、路径越界、任意命令执行级未解决缺陷。
5. 性能测试有记录；未达目标的调整有评审结论。
6. 依赖版本、许可清单、兼容版本、已知限制、升级/回退说明齐全。
7. 用户能理解“未保存内容不管理”“备份不含正文”“短词查询可能较慢”。
8. 无 Python 的目标机器能运行完整发布包，SQLite 功能和外部编辑器集成与开发入口一致；窗口关闭后无管理器工作线程或第二实例继续写库。
9. Python/wxPython 的确切版本、二进制架构和已验证 OS 公开记录；上游支持状态与本项目实测兼容性分开说明。

## 8. 后续开发首批任务

设计通过后依次：

1. 只读检查项目可用 Python、pip、架构、wheel/PyPI 连通性；不把此前其他工具链检查结果视为通过。
2. 在实施阶段创建独立 `.venv`，验证 CPython 3.13 x64 与 wxPython 4.2 系列组合并锁定依赖；无兼容 wheel 时先评审，不静默源码编译。
3. 建立 wx 主窗口、虚拟列表、只读预览和 pytest 最小工程，检查线程回调、中文/emoji 位置与退出流程。
4. 实验验证 sqlite3 FTS5、短词回退、watchdog 与原子保存、Windows 路径和在线备份恢复。
5. 尽早构建最小 PyInstaller onedir 包并在目标 OS 验证，再实现文档库到编辑器打开的完整闭环。

上述环境、最小工程、FTS5、监听及打包步骤已开始执行；精确完成程度以迭代日志为准。自动迭代继续优先修复可复现问题和未达标项。
