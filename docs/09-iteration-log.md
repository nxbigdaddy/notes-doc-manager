## 第三轮：0.2.0 自动保护与文件重新关联

### 本轮已实现

1. **每日自动元数据备份**：按UTC自然日、有管理信息变化才生成；成功时间、指纹及快照所有权持久化。内部维护时间和索引派生字段不导致无意义备份。
2. **安全轮换和健康检查**：只轮换最近7次自己登记成功的自动快照，保护/未知文件不删除。失败、取消、发布记账失败不先清理旧备份；支持时钟回拨。当前快照缺失、截断、页头异常、链接或同名替换会重新触发保护。
3. **手动重新定位**：缺失记录可选择同库现有文件。若新路径已被自动登记为无人工信息占位，需要额外确认后合并管理记录，保留旧ID、标签、收藏、打开信息与编码。目标有人为信息或旧文件仍存在则拒绝；不移动或写回正文。
4. **跨重启内容核验**：每库保存成功时间，启动时核验逾期、损坏或未来时间戳；重读可索引正文，能发现大小/mtime不变的变化。未完成、取消、读取失败不推进成功时间。
5. **有界重试**：瞬态错误使用0.5/1/2/4/8秒五次退避，不占用读取线程sleep；按文档代际和租约token拒绝过期结果。停止扫描会使已排队及执行中的重试失效，新文件事件可触发新代际。
6. **GUI**：常驻备份状态、最后成功时间、立即备份/详情，缺失文件重新定位按钮和确认流程；保持异步代际/关闭保护。
7. **发布对应性**：打包时嵌入源码哈希，冻结验证对照当前源码及应用版本，不能给旧exe附上新源码清单冒充构建成功。

### 本轮发现并修复的边界

- 读失败的内部刷新曾不断重置重试计数：39个测试周期读79次；现严格为初读加最多5次，区分读取不稳定与登记元信息落后。
- 扫描结束但重试已排队时，停止操作原先不能使重试失效；现队列清除/token检查阻止迟到提交。
- 备份只按日期排序可能在时钟回拨时删除最新快照；改为持久化登记顺序。
- 已删除/损坏/被替换的快照不能因指纹未变而一直报告“已备份”。
- 备份成功后的维护错误不能导致永久clean+failed；健康保护已覆盖时可恢复状态。
- 占位合并必须传字面布尔值True，不能用字符串等truthy参数绕过明确确认。
