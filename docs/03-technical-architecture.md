# 03 — 技术架构

> v0.8：Python + wxPython + SQLite 已迭代至0.6.0快速打开候选。以下保留设计目标；实际取舍和未达标项见第8～13节及迭代日志。

## 1. 技术选型

官方资料编号见 [07](07-decisions-and-references.md)。语言、GUI 和数据库路线已确定；补丁版本、监听与打包依赖在 M1 验证后锁定。

| 层次 | 设计选择 | 说明 |
|---|---|---|
| 平台 | Windows x64、本地 NTFS | Windows 11 暂定正式验收；本机 Windows 10 Pro 22H2 做兼容验证 |
| 语言 / 运行时 | Python；暂选 CPython 3.13 x64 标准构建 | 优先验证与 wxPython wheel、打包工具匹配，不使用 free-threaded 或预发布构建 [S1] |
| GUI | wxPython，暂选 4.2 系列 | 原生风格桌面控件；列表和只读预览见 UI 设计 [S2] |
| UI 组织 | MVP：View + Presenter + 显式界面状态 | 通过构造参数传依赖，不引入大型 GUI 架构框架 |
| 持久化 | Python 标准库 `sqlite3` | 参数化 SQL、显式事务、SQL 迁移；不引入 ORM [S4] |
| 正文检索 | SQLite FTS5 trigram + 字面回退查询 | 检测实际 SQLite 构建能力，不仅判断 Python 版本 [S5] |
| 文件检测 | `watchdog.Observer` + 补偿扫描器 | 隔离为适配层，不假设事件完整、不重复或必定报告溢出 [S6] |
| 后台任务 | `threading`、`queue`、有限工作线程 | 结果通过 `wx.CallAfter` 返回主线程；不混用第二套 GUI 事件循环 [S3] |
| 编辑器集成 | 标准库 `subprocess.Popen` | 参数列表、`shell=False`，不等待编辑器退出 [S7/S8] |
| 测试 / 检查 | `pytest`、`ruff` | 开发依赖，不随应用作为开发工具分发 |
| 日志 | 标准库 `logging` + 滚动文件处理器 | 只记诊断元信息，不记录正文、搜索词和敏感路径 |
| 打包 | PyInstaller `onedir` / windowed | Windows x64 目录包，在无 Python 的机器验证 [S11] |

不引入浏览器内核、HTML/CSS/JavaScript 前端、HTTP 服务或独立数据库服务。首版不编译 Notepad3，也不以安装 Visual Studio 作为项目运行前提。

## 2. 工程结构与依赖方向

拟采用单个 Python 应用包、`src` 布局，避免照搬多项目桌面工程：

| 拟建位置 | 职责 |
|---|---|
| `src/notes/__main__.py`、`bootstrap.py` | 应用入口、日志、单实例、服务组装和关闭协调 |
| `src/notes/ui/` | wxPython View、Presenter、页面状态和界面线程调度 |
| `src/notes/application/` | 用例、任务协调、接口（`typing.Protocol`）与结果 DTO |
| `src/notes/domain/` | 文档身份、规则、状态、`dataclass` / 枚举，不导入 GUI 和 SQLite |
| `src/notes/infrastructure/` | sqlite3、watchdog、文件 IO、Notepad3、备份及 Windows 适配 |
| `src/notes/resources/` | 图标等只读资源，显式纳入打包清单 |
| `tests/` | 单元、真实 SQLite、临时文件系统和打包冒烟测试 |
| `packaging/notes.spec` | PyInstaller 收集规则、图标和 Windows 清单 |
| `pyproject.toml` | 包元数据、Python 约束、直接依赖与测试检查配置 |
| `requirements-win-x64.lock.txt`、`requirements-dev-win-x64.lock.txt` | 运行/开发依赖的完整版本与哈希；开发锁与运行锁不得冲突 |

以上路径为拟建结构，不表示文件已经存在。

依赖方向：View → Presenter → Application → Domain；Infrastructure 实现 Application 接口。只有 bootstrap 组装具体适配器。数据库连接、wx 对象和文件句柄不通过跨线程 DTO 传递。

## 3. 核心服务契约

以下为语义契约，不是最终 Python 签名。耗时操作接受取消信号和请求 ID，结果包含状态、错误码及范围是否完整。

| 服务 | 主要操作 |
|---|---|
| LibraryService | 添加、停用、启用、修改规则、刷新文档库 |
| DocumentService | 列表、创建、收藏、最近打开、缺失记录重新定位 |
| TagService | 标签增删改、设置文档标签 |
| PreviewService | 稳定读取、解码、截断预览 |
| SearchService | 查询、分页、覆盖统计、超时和取消 |
| IndexCoordinator | 有界排队、去重、重试、代际校验、重建 |
| FileScanner | 范围枚举、变化发现、扫描覆盖结果 |
| FileChangeMonitor | watchdog 事件适配、健康检查、异常与疑似漏失提示 |
| ExternalEditor | 校验配置、发出打开请求、可选定位行 |
| MetadataBackupService | 一致性快照、JSON 导出、校验、替换恢复 |
| WindowsPlatformAdapter | 路径比较、共享只读句柄、单实例与窗口激活 |

错误至少区分：参数错误、路径越界、重名、权限不足、库离线、文件缺失、编码待确认、读取忙、编辑器无效、数据库错误、能力不支持、超时和取消。

## 4. 后台任务与并发

- GUI 主线程运行 `wx.App` 主循环，仅处理短事件与界面更新；扫描、解码、SQL 和备份不在 GUI 线程执行。
- 后台通过 `wx.CallAfter` 提交不可变结果 [S3]；Presenter 检查请求代际与 closing 标记。每次批量刷新，避免每个文件都投递 GUI 回调。
- 单个写入线程拥有两个数据库各自的写连接，串行处理写请求；读任务在自己的工作线程创建并关闭独立连接。保留 `check_same_thread=True`，不靠关闭保护来共享连接 [S4]。
- 文件读取默认并发 2；耗时搜索使用独立受限队列，避免短词查询占满预览任务。线程数与数据库内存占用需实测。
- 常规 CPython 的工作线程不是纯 Python CPU 密集任务的无限并行方案 [S16]；先使用分批、限速和取消。只有测量证明需要时再评估进程池，并补冻结打包与关闭设计。
- watchdog 回调只发送变化提示，不读正文、不写数据库、不改控件。用户任务队列上限初值 10,000，饱和时标记 dirty 库并合并范围；还须监测监听器内部事件积压。
- 按“文档 ID + content_generation”去重；旧任务结果在提交索引及更新 UI 前都要检查代际。
- 搜索输入防抖 250 ms；预览、搜索遵循最后请求有效。取消使用 `threading.Event` 并在分批处理间检查；SQLite 长查询增加进度回调检查取消/超时。
- 不用 `Future.cancel()` 代替正在运行任务的协作取消，不用 `wx.Yield()` 轮询模拟后台处理。
- 关闭时停止接单、设置取消信号、停止并等待监听器与工作线程、完成或回滚短事务、在连接所属线程关闭数据库，最后销毁窗口。用主循环回调展示收尾状态，不在关闭事件里无限 `join()`；不依赖 daemon 线程被强杀来保存数据。
- 下次启动对未完成索引重新核验；不把未持久化任务队列当唯一恢复信息。

## 5. Notepad3 集成

官方文档说明可传入文件路径，`/g` 可指定行列；所用版本仍需实测 [S8]。

1. 用户确认 Notepad3 的绝对 `.exe` 路径，不通过 PATH 搜索、不自动下载。
2. 基础调用相当于 `subprocess.Popen([editor_path, document_path], shell=False)`，不手工加引号、不拼接 shell 字符串 [S7]。
3. 拒绝以 `.bat`、`.cmd` 或任意命令模板作为编辑器配置；这不替代对所选可执行文件来源的信任判断。
4. 不等待编辑器退出，不修改编辑器 INI、系统关联和窗口复用策略；成功创建进程只代表打开请求已发出。
5. 可选行号由内部正整数生成，开关在文件路径之前；定位失效时退回普通打开。
6. 不终止现有编辑器、不模拟按键、不读取内存或推测“已保存”。
7. PyInstaller 会调整运行环境；冻结应用启动外部程序前应按打包工具指引隔离继承的 DLL 搜索设置，防止把管理器的依赖带给 Notepad3。该处理封装于 Windows 适配层并单独测试 [S18]。

兼容矩阵：中文、空格、括号、`&`、扩展 Unicode 字符、长路径；编辑器已运行/未运行；只读/缺失文件；不同窗口复用设置；源码运行/冻结发布两种入口。

已在 2026-09-15 本机检查发现 `D:\Program Files\Notepad3\Notepad3.exe`，版本 7.26.426.1。此信息仅作为本机测试候选，不硬编码进应用，也不表示已完成参数兼容测试。

## 6. 配置和运行数据

继续使用用户级应用数据目录：

- `%LOCALAPPDATA%\Notes\metadata.db`：标签、记录、设置，必须备份。
- `%LOCALAPPDATA%\Notes\search-v2.db`：0.3.0的可重建正文缓存和索引；旧search.db保留、不共用结构。
- `%LOCALAPPDATA%\Notes\backups\`、`logs\`：备份和限量诊断日志。

应用目录、资源目录与运行数据分离；不向源码目录、PyInstaller 解包目录或程序安装目录写管理数据。项目名称仍待确定。

应用数据路径由统一适配层解析；禁止将其自身、子目录或包含它的根目录配置成文档库。数据库保持本地，不放网络盘、同步盘；不自动读取云占位文件。

配置与备份采用受校验的 JSON，不用 `pickle`、`eval` 或可执行 Python 脚本充当导入格式。

## 7. 依赖与发布

### 7.1 开发环境

- 使用项目专用 `.venv`、`python -m pip`，不复用系统全局或其他项目的环境。
- M1 首先验证 CPython 3.13 x64 与 wxPython 4.2 系列的 Windows wheel 组合；优先二进制安装，不在缺少 wheel 时静默转为源码编译。若失败则评审可用的受维护组合，更新文档和锁文件。
- `pyproject.toml` 声明依赖；锁文件固定直接及传递依赖、wheel 哈希，构建工具本身也锁版。Python 补丁、架构、wxWidgets 和 SQLite 实际版本写入构建记录。
- wxPython、watchdog 为应用直接第三方依赖；SQLite、线程、子进程和日志优先使用标准库。测试检查与 PyInstaller 属于开发/构建依赖。
- 禁止在运行时自动 pip 安装、更新依赖，或从用户目录动态加载 SQLite 扩展。
- v0.2 时 Python 环境尚未核验；v0.3 已完成独立虚拟环境与本机原型验证，实际版本记录见第 8 节。不得将本机通过外推为所有 Windows 版本兼容。

### 7.2 发布包

- 在 Windows x64 上构建 PyInstaller **onedir** GUI 目录包，先验证目录包，再评估 onefile；不承诺切换 Python 后包体积和启动时间自动更小 [S11]。
- 构建清单显式收集 wxPython 的原生组件、`wx.stc`、SQLite、watchdog Windows 后端、编码模块、图标和迁移 SQL。检查缺失 DLL、动态导入和资源路径。
- 发布包以无需单独安装 Python 为验收目标；不要求用户装开发工具，但仍要检查目标系统运行库和二进制兼容性。
- 无管理员权限、无自启动、无系统关联修改；发布 GUI 默认不弹出控制台，异常进入日志并显示可理解的错误提示。
- 程序未安装 Python 的干净 Windows 11 x64 环境做正式验收；本机 Windows 10 Pro 22H2 x64 另做兼容验证，不把前者成功推断为后者兼容。
- 升级先备份元数据，执行事务迁移；不兼容的旧程序拒绝写入新库。首版无自动更新。
- 发布前检查所有 Python wheel、原生库和打包工具的许可与安全信息、签名方案、来源和更新策略；默认不捆绑 Notepad3。

## 8. 首轮实际实现登记（2026-09-15）

- **运行时**：本机 CPython 3.14.0 x64，项目独立 `.venv`；wxPython 4.2.5/wxWidgets 3.2.9，SQLite 3.50.4，watchdog 6.0.0，PyInstaller 6.22.3。未依赖其他项目目录中的 3.13 安装。
- **工程**：`src/notes`、`tests`、`scripts`、PyInstaller spec 与开发/运行哈希锁文件已建立；当前应用版本 0.1.0。
- **数据连接**：Store 每次调用在当前线程打开/关闭连接，保留线程保护；应用单写任务队列与 Store 锁共同串行化。不是设计初稿中“永久持有两个写连接”的实现。每 50 条批量提交正文，减少频繁 WAL 关闭/检查点成本。
- **一致性**：文件监听合并具体相对路径，已收到事件的文档即使大小和 mtime 不变也重新验证。事件集合不确定/过量或监听健康重启时强制补偿。跨重启的每日哈希调度尚需增强。
- **恢复**：采用元数据数据库内单事务替换，之前先做 SQLite 保护快照；不在线替换 metadata.db/WAL/SHM 文件。JSON 不迁移机器设置，编辑器路径恢复后须重新确认。
- **界面**：原生三栏、虚拟列表、只读预览、中文状态、标签/收藏/规则/备份对话框、取消、请求代际和关闭流程已接通；外观目视审查未完成。
- **验证**：本机源码/冻结包隔离自测与隐藏 GUI 可运行；仍缺干净 Windows 11、真实编辑器完整交互、签名及部分设计边界。
- **限制**：详细性能和功能缺口见 [09](09-iteration-log.md)，不得据这一登记将 M4 标为完成。

## 9. 0.2.0 实现补充

- **自动保护**：按UTC自然日及管理信息指纹判断备份到期，忽略索引派生字段和内部维护记账。自动快照只轮换自己登记的最近7次成功产物，恢复前保护快照不删除。
- **重新定位**：异步检查、正常确认和无人工信息占位的额外确认；事务中再次验证。只改变管理关联，保留原ID和人工信息，不新增物理文件操作。
- **跨重启核验**：持久化每库成功时间；应用启动时对过期、损坏或异常未来时间安排完整内容重读。取消、不完整枚举、读取失败不推进成功标记，重试延迟用单调时钟。
- **读取重试**：瞬态错误进入有界 `RetryQueue`，不在IO线程sleep。读不稳定与登记元信息落后分开处理，扫描不能把同代际已耗尽的尝试无限重置。
- **后台界面**：GUI显示备份状态和最后成功时间，可提前备份、重新定位缺失项；回调继续检查关闭状态及选中项代际。
- **发布**：新版本发布于独立 `dist/0.2.0/Notes`，不覆盖旧版本目录、不结束用户进程。BAT优先新版本。打包时嵌入源码哈希，冻结验证必须与当前源码和版本一致。
- **仍未完成**：不依赖用户确认的可靠外部rename身份跟踪、大库性能优化、损坏启动恢复和完整发布验收等见迭代日志。

## 10. 0.3.0 缓存与检索改进

- 缓存隔离为 `search-v2.db`，external-content FTS5由触发器维护，正文只在本缓存的正文表保存一次。旧search.db不变，避免旧exe与新触发器双写。
- 新缓存/已知模式迁移先失效元数据代际，再事务创建缓存；异常只能造成可重建索引待处理，不清除标签/收藏。未知未来版本拒绝覆盖。
- SQL完成过滤、代际覆盖、字面候选、排序和分页；只为当前页创建DTO/摘要。最近打开按打开时间、限定100条，非法查询和SQLite忙不使健康缓存失效。
- 正式应用仍采用每50条短事务批量索引。空闲锚连接 `index_session` 仅保留实验接口，因大集实验异常尚未解释，**不在0.3.0应用扫描路径启用**。
- 冻结验证使用每次全新隔离目录，并保存版本化记录，防上次残留DLL掩盖缺依赖；发行包含自足使用说明。
- 已测样本与未达标项见09，不能将GUI小样本或实验接口数据冒充当前应用大库性能。

## 11. 0.4.0 直接文件移动跟踪

- Scanner通过真实Path.stat收集可用NTFS设备/文件编号/出生时间组合；不使用Windows DirEntry可能为零的身份字段，不把硬链接或未知平台强行当单文件身份。
- Monitor原子保留ChangeBatch，epoch隔离旧订阅；事件集合不可靠时只做补偿扫描，不自动关联。
- Service限制提示新鲜度、直接文件及无冲突关系；Store事务内两次验证目标事实、旧路径缺失及人工信息，再保持原ID更新管理路径并失效旧索引。
- 可选派生身份表不改变Document列或metadata schema1，JSON与管理dirty排除身份。旧版固定列操作兼容，无法建立可信基线时保守降级。
- 监听、扫描和文件操作都先验证卷再访问路径，防已保存盘符后来重映射为网络盘/非NTFS；只做模拟边界测试，不访问真实网络。
- 程序不执行移动/删除；关闭期间、跨库、目录、链/冲突、硬链接等仍用缺失记录和手动重新定位兜底。

## 12. 0.5.0 启动恢复与实际运行时

- SingleInstance之后、ApplicationService之前执行RecoveryManager续作/只读检查，损坏/丢失历史主库不由Store隐式补空。
- RecoveryDialog单后台worker，明确确认后提交；恢复后再验证健康和journal完成，尊重用户退出意图。
- JSON/SQLite仅作受验证逻辑输入；故障main/sidecars保全后才安装清洁新库，未知阶段不猜测覆盖。详见10。
- 官方CPython3.14.7 NuGet仍带旧SQLite，故项目私有runtime另配置经过官网SHA3核验的3.53.4 x64 DLL；系统Python、DLL、注册表、PATH不变。
- 程序启动拒绝已知WAL-reset受影响引擎，发行校验版本及官方DLL哈希；旧包不再作为BAT自动回退。
- 新效率功能按用户再次授权接续：快速打开、模板、智能列表，分版本验收，不混入本轮恢复提交。

## 13. 0.6.0 快速打开与短动作通道

- 查询取消按main/quick隔离；快捷文件名查询有独立容量，不能被后台命令队列挤占。
- 用户打开请求及相关短偏好操作不排在整库扫描后，但Store仍串行SQL；最终打开快照受短门锁保护，避免并发重定位后打开旧路径的另一文件。
- 快捷键适配器使用Windows系统DLL、专用有效ID和NOREPEAT；默认不注册，可注入后端，退出清理。应用内Ctrl+P不依赖全局注册。
- Quick小窗无正文编辑/预览，输入与结果有代际防护；排队的打开可取消，已发出的请求不杀用户进程。
- 新增隔离quick-smoke，拒绝与自定义data-dir合用，避免自动测试扫描真实用户库；冻结版验证不真正注册热键或启动编辑器。

## 14. 0.7.0 有限内置模板

- `domain/templates.py`持有不可变定义和纯渲染器，无文件加载、脚本执行或模板引擎依赖。单遍白名单替换，冻结时间快照，严格文本大小限制。
- 服务分离纯预览与实际创建；预览不创建文件，创建按当时的时间重新渲染，不信任GUI回传正文。
- 文件层独占新建后完整写入/同步，任何创建后异常保留现场并返回`created_partial`。应用安排补偿扫描，界面不得把部分成功误报为完全未创建。
- 沿用登记、索引、监听、元数据备份和恢复；模板定义不持久化，不迁移metadata schema，不需要另备份模板配置。
- 纯单元、真实隔离文件、隐藏GUI与冻结自测覆盖边界；不以模板功能测试替代大型文档库性能或真实编辑器验收。详见11。

## 15. 0.8.0 智能列表与格式升级

- 纯域校验名称与八种固定过滤字段，版本化JSON拒绝未知键、重复key和未来版本，所有文本仍交给参数化字面搜索。
- 智能列表为管理信息，不放入会被恢复忽略的机器settings；首次成功保存前保护旧库，在同一事务内建表/插入/升schema2。未使用功能不强制升级。
- Store同一门锁下重新读取保存定义、校验现存引用并调用既有查询，页面只传列表ID与分页。失效引用保留，查询失败不放宽。
- JSON format2和SQLite schema2成对校验，旧版拒绝新数据；当前版接受v1备份，明确替换时清空列表但在线restore不降schema版本。
- 启动恢复安全白名单扩展至新表及源版本选择，继续严格校验坏行、原件保护与中断决策；可携带筛选不等于可恢复编辑器/热键设置。
- GUI使用独立活动列表ID与请求代际，避免普通导航的过期过滤清理逻辑放宽列表。详见12。
